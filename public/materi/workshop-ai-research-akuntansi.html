Ide — Dua Tools, Satu Alur

OpenCode — sang agen

  • Agent dengan GUI (Windows/Mac), tanpa terminal
  • "Tangan": baca/tulis file, jalankan kode, akses web & API

Obsidian — memori & ruang kerja

  • Vault = folder berisi file Markdown
  • Graph muncul otomatis dari [[wikilink]]
OpenCode (agen)→ Vault Obsidian→ Python (analisis)→ Overleaf (paper)

Ide — Model Gratis & Jebakan Privasinya

Big Pickle, MiMo Free, Ling Free — data boleh dipakai memperbaiki model selama masa gratis.

Nemotron Free (NVIDIA) — trial use only, jangan kirim data pribadi/rahasia; sesi dicatat.

Muse Spark Contributor Free — prompt & jawaban dipakai melatih model Meta.

Space Bunny Free — zero-retention, tidak dipakai untuk training.

Konsekuensi: "gratis" ≠ "aman". Semua praktik kita memakai data publik.

Ide — Vault Dimulai dari Kosong

Kita tidak membagikan vault jadi. Agen sendiri yang membangun struktur — bukti agentic yang sebenarnya.

vault/
├── literatur/
│   ├── _index.md       ← MOC: peta literatur
│   ├── catatan/        ← catatan literatur (bertag & bertaut)
│   └── pdf/            ← PDF asli (arsip + anotasi)
├── data/               ← dataset
├── draf/               ← tulisan & paper
├── _templates/         ← template catatan
└── AGENTS.md           ← konvensi penautan untuk agen

AGENTS.md = infrastruktur kunci: karena peserta tidak mengetik Markdown, agen harus tahu konvensi kita.

▶ Praktik 2 — Prompt #1

Agen Membangun Vault

Kamu asisten riset saya. Buat struktur vault riset ini:
folder literatur/catatan, literatur/pdf, data, draf, _templates.
Buat _templates/literatur.md dengan frontmatter: title, authors,
year, journal, doi, tags; bagian Ringkasan, Metode, Temuan Kunci.
Buat AGENTS.md berisi konvensi penautan: catatan disimpan di
literatur/catatan/NamaDepan-Tahun-Judul.md, tautkan ke [[_index]]
dan teori terkait, beri tag #metode/... dan #topik/....
Hasil: folder, template, dan AGENTS.md muncul sendiri di vault Anda.

Ide — Pencarian Literatur: Manual & Agen

Manual — untuk kualitas

  • Google Scholar
  • Scopus / Web of Science (langganan kampus)
  • Garuda & SINTA (konteks Indonesia)

Peneliti yang menilai kata kunci & kualitas jurnal.

Agen — untuk melengkapi

  • Cari via API terbuka: OpenAlex, Crossref
  • Cek status open access (Unpaywall)
  • Unduh PDF open access ke literatur/pdf/

Metadata dari API — bukan dari ingatan model.

▶ Praktik 3 — Prompt #2

Agen Mencari & Mengunduh PDF

Topik: "audit quality and earnings management".
Cari 5 artikel lewat API OpenAlex/Crossref (jangan dari ingatan).
Untuk tiap artikel tampilkan judul, penulis, tahun, jurnal, DOI,
dan status open access. Unduh PDF yang open access ke literatur/pdf/
dengan nama Penulis-Tahun-JudulSingkat.pdf.
Jangan unduh artikel berbayar.
Hasil: PDF open access tersimpan di literatur/pdf/ + daftar metadata (DOI) dari API.

Ide — PDF ke Obsidian: Perlu Dikonversi?

Untuk dibaca manusia

PDF bisa langsung dimasukkan ke vault (penampil PDF bawaan, bisa dianotasi). Tanpa konversi.

Untuk dibaca agen

PDF itu biner — agen tak bisa membaca isinya atau menautkannya. Isinya perlu jadi teks/Markdown.

Jawaban: dua-duanya. PDF untuk arsip; catatan Markdown untuk graph & tautan. Agen mengekstrak dengan markitdown, docling, pymupdf4llm, atau pdftotext.

▶ Praktik 4 — Prompt #3

PDF → Catatan Bertaut → Graph

Baca PDF di literatur/pdf/Smith-2023.pdf. Buat catatan literatur

Hasil: catatan Markdown muncul di literatur/catatan/, bertaut, dan titik baru muncul di graph Obsidian.

Ide — Konvensi Penautan & Graph

Agen: ekstrak → ringkas → isi frontmatter → simpan catatan MD → tambahkan [[wikilink]] → beri tag.

[[_index]]            ← MOC: peta literatur
[[Teori-Agency]]      ← tautan ke teori terkait
#metode/kuantitatif   ← tag metode
#topik/audit          ← tag topik

Hasil: graph tumbuh sendiri — klaster tema & teori terlihat. Peserta tidak mengetik Markdown.

Ide — Analisis Kuantitatif: Dua Lapis

Aman Lapis 1 — Sintaks

Agen menulis sintaks Stata/SPSS dari deskripsi struktur data & hipotesis — bukan datanya.

Peneliti menjalankan sendiri. Model tidak menyentuh data mentah.

Data publik Lapis 2 — Python

Agen menulis dan menjalankan kode (pandas, statsmodels, linearmodels).

Output masuk ke percakapan → hanya untuk data non-sensitif.

"Biarkan data tinggal di tempatnya. Yang masuk ke agen hanya instruksi dan kode."

▶ Praktik 5 — Prompt #4

Agen Menulis Sintaks (Data Tidak Dikirim)

Struktur data saya: kolom invest, value, capital; unit = firma;
waktu = tahun. Tulis sintaks Stata untuk regresi fixed effects
invest pada value dan capital, dengan efek tetap firma dan tahun.
Jangan minta datanya.
Hasil: sintaks Stata siap tempel — tanpa satu baris pun data Anda keluar dari laptop.

Ide — Studi Kasus Kuantitatif: Grunfeld

  • Data panel firma × tahun — publik & klasik
  • Cocok untuk regresi fixed / random effects
  • Alur: sintaks Stata dulu → lanjut Python dijalankan agen
invest ~ value + capital      (unit = firma, waktu = tahun)
▶ Praktik 6 — Prompt #5

Agen Menjalankan Python (Data Publik)

Gunakan dataset Grunfeld. Jalankan regresi panel fixed effects
invest pada value dan capital; tampilkan hasil dan interpretasi
singkat.
Hasil: tabel regresi + interpretasi, dijalankan agen atas data publik.

Ide — Analisis Kualitatif: Transkrip Sintetis

  • Transkrip wawancara asli rahasia → praktik memakai transkrip sintetis
  • Agen memberi first-pass coding tematik + menyusun codebook sebagai catatan
  • Kutipan pendukung ditandai; agen tidak menarik kesimpulan

Rigor tetap milik peneliti: reliabilitas, transparansi, audit trail, intercoder agreement. Agen = asisten.

▶ Praktik 7 — Prompt #6

First-Pass Coding

Lakukan first-pass coding tematik pada data/transkrip-sintetis.md.
Buat codebook di literatur/catatan/codebook.md, tandai kutipan
pendukung, dan jangan menarik kesimpulan.
Hasil: codebook awal + kutipan bertanda — bahan untuk Anda validasi.

Ide — Menulis Paper: Mulai dari Jurnal

  • Agen menelusuri kesesuaian naskah dengan scope/aims jurnal
  • Verifikasi wajib: ISSN, indexing (Scopus/SINTA), kuartil, APC — ke Scimago / laman jurnal / SINTA
  • Jangan percaya impact factor/kuartil yang diketik model
Cari jurnal→ Template LaTeX→ Draf→ Overleaf
▶ Praktik 8 — Prompt #7

Cari Jurnal & Siapkan Template

Berdasarkan draf/kerangka.md, carikan 3 jurnal akuntansi yang cocok
(sebutkan scope & alasan, jangan mengarang impact factor).
Lalu siapkan template LaTeX jurnal pilihan di draf/paper/ dan
susun struktur .tex.
Hasil: rekomendasi jurnal + kerangka .tex siap diunggah ke Overleaf.

Ide — Draf & Sitasi yang Bisa Dipercaya

  • Agen menyusun kerangka: Pendahuluan, Literatur, Metode, Hasil, Diskusi — dari catatan vault
  • Sitasi: refs.bib diambil dari DOI/Crossref, bukan dari ingatan model
  • Setiap klaim yang perlu diperiksa ditandai

AI bukan penulis. Manusia pemilik isi & penanggung jawab setiap klaim.

▶ Praktik 9 — Prompt #8

Draf Paper → Overleaf

Susun draf bagian Pendahuluan & Metode dari catatan di
literatur/catatan/. Buat draf/paper/refs.bib dari DOI catatan
(ambil entri BibTeX dari Crossref, jangan menulis dari ingatan).
Tandai semua klaim yang perlu saya verifikasi.
Hasil: unggah draf/paper/ ke Overleaf → kompilasi → PDF paper terbentuk.

Ide — Etika Penulisan & Data

  • AI bukan penulis. Banyak jurnal melarang AI sebagai author dan mewajibkan disclosure.
  • Hanya open access. Jangan membajak artikel berbayar; akses lewat langganan perpustakaan.
  • Data tinggal di tempatnya. Data sensitif tidak masuk ke agen / model gratis.
  • Verifikasi sitasi & metrik dari sumber resmi; hak cipta: kutipan secukupnya.

Kalau Tertinggal — Ada Checkpoint

  • Vault cadangan yang sudah selesai: catatan, data, dan draf — bisa ditimpa/diunduh
  • Folder draf/paper/ lengkap (.tex + refs.bib) sebagai hasil akhir rujukan
  • PDF contoh lokal bila jaringan/API melambat

Tujuannya: tidak ada peserta yang tertinggal karena satu langkah gagal.

Ringkasan

  • Agentic AI = AI yang mengerjakan tugas di folder Anda, bukan sekadar menjawab di chat
  • OpenCode + Obsidian = agen + memori berbasis file Markdown
  • Literatur: manual untuk kualitas, agen untuk cari & unduh PDF open access
  • Ringkas & penautan: catatan bertaut otomatis → graph tumbuh sendiri
  • Analisis: sintaks untuk data asli, Python untuk data publik
  • Paper: cari jurnal → template LaTeX → draf → Overleaf
  • Prinsip: data tinggal di tempatnya; AI bukan penulis; verifikasi selalu

Mulai dari Satu Topik

Tidak perlu langsung seluruh alur. Mulai dari satu topik, lima PDF, lima catatan — lalu graph tumbuh sendiri.
