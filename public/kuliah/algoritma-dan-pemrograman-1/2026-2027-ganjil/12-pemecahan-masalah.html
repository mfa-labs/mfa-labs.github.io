Bagian 02

Enam langkah

Cara yang bisa diulang untuk masalah apa pun.

Urutannya

Langkah pemecahan masalah

  • Pahami masalahnya — bisa menceritakannya ulang
  • Pisahkan masukan, proses, dan keluaran
  • Pecah menjadi bagian yang lebih kecil
  • Pilih struktur kendali untuk setiap bagian
  • Tulis pseudocodenya
  • Telusuri dan uji kasus batas

Bagian 03

Memilih struktur kendali

Inti pekan ini: mengenali struktur dari bentuk soalnya.

Runtunan, seleksi, atau iterasi?

Tiga pertanyaan penentu

PertanyaanKalau ya
Semua langkah dikerjakan sekali, lurus?Runtunan
Ada langkah yang hanya dikerjakan bila syarat tertentu?Seleksi
Ada langkah yang harus dikerjakan berulang kali?Iterasi

Satu pertanyaan lagi

Bentuk iterasi yang mana?

PertanyaanStruktur
Jumlah putaran sudah diketahui di awal?FOR
Jumlah putaran bergantung keadaan?WHILE
Harus berjalan minimal sekali?REPEAT

FOR dan WHILE adalah yang paling sering dipakai.

Bagian 04

Kasus batas

Algoritma bisa benar untuk contoh umum, tetapi salah pada nilai ekstrem.

Yang selalu layak diuji

Kasus batas

KasusPertanyaan
nolApakah masukan kosong atau nol ditangani?
negatifApakah tanda negatif masuk akal di sini?
satuApakah pengulangan yang seharusnya sekali tetap berjalan?
tepat di batasNilai yang persis sama syarat masuk ke cabang mana?
paling besarApakah hasilnya masih masuk akal?

Yang paling sering luput

Nilai tepat di batas.

Nilai 85 pada contoh nilai huruf, atau baris pertama dan terakhir pada pengulangan, keduanya menuntut pemeriksaan khusus.

Bagian 05

Tiga contoh soal cerita

Dari indeks massa tubuh sampai bilangan prima.

Contoh 1

Kategori indeks massa tubuh

DEKLARASI berat, tinggi : real bmi : real BEGIN READ berat, tinggi bmi ← berat ÷ (tinggi × tinggi) IF bmi < 18.5 THEN WRITE "kurang" ELSE IF bmi < 25 THEN WRITE "normal" ELSE IF bmi < 30 THEN WRITE "berlebih" ELSE WRITE "obesitas" ENDIF END

Kasus batas: tinggi nol — pembagian dengan nol harus ditolak lebih dulu.

Contoh 2 — penanda berhenti

Rata-rata sampai data habis

DEKLARASI nilai, total, cacah : integer rata_rata : real BEGIN total ← 0 cacah ← 0 READ nilai WHILE nilai ≠ −1 DO total ← total + nilai cacah ← cacah + 1 READ nilai ENDWHILE IF cacah > 0 THEN rata_rata ← total ÷ cacah WRITE rata_rata ELSE WRITE "belum ada data" ENDIF END

Dua hal penting

Kenapa begitu?

01READ muncul dua kaliWHILE memeriksa kondisi sebelum badan berjalan — nilai pertama harus ada lebih dulu
02Pemeriksaan cacah > 0Mencegah pembagian dengan nol bila pengguna langsung mengetik −1

Contoh 3 — pengulangan bisa nol kali

Bilangan prima

DEKLARASI n, i : integer prima : boolean BEGIN READ n IF n ≤ 1 THEN prima ← false ELSE prima ← true FOR i ← 2 TO n − 1 DO IF n mod i = 0 THEN prima ← false ENDIF ENDFOR ENDIF IF prima THEN WRITE "prima" ELSE WRITE "bukan prima" ENDIF END

Perhatikan untuk n = 2

FOR bisa tidak berjalan sama sekali.

Batas 2 TO n − 1 untuk n = 2 menjadi 2 TO 1 — lebih kecil dari awal, sehingga pengulangan dilewati dan prima tetap benar.

Bagian 06

Merapikan rancangan

Rancangan yang benar belum tentu rancangan yang baik.

Bandingkan

Dua versi yang hasilnya sama

Berantakan

READ a IF a > 100 THEN WRITE "besar" ELSE WRITE "kecil" ENDIF

Lebih baik

READ nilai IF nilai > 100 THEN WRITE "di atas batas" ELSE WRITE "dalam batas" ENDIF

Bedanya bukan pada hasil, melainkan pada kemudahan diperiksa.

Hindari

Kesalahan yang sering muncul

  • Menulis pseudocode sebelum masalahnya dipahami
  • Langsung mencari struktur kendali tanpa memisahkan masukan-proses-keluaran
  • Tidak menguji kasus batas
  • Lupa bahwa pengulangan bisa berjalan nol kali
  • Pembagian dengan nol ketika akumulatornya masih kosong
  • Menganggap rancangan selesai tanpa penelusuran
